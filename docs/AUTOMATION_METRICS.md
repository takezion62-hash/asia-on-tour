# 第5段階：自動解消率・自動掲載率の計測

新着・過去の各安全統合後に既存の auto-sync-status.json / history-sync-status.json の automationMetrics (version 1) を更新する。追加 API、ワークフロー、戦績/賞金/承認条件の変更なし。GitHub への push が成功した場合のみ計測も保存される。既存ログの累計から過去の率を逆算しない。

- 自動解消率 = (開始時キューのうち今回安全統合で新規掲載された ID + 開始時点ですでに同一 ID・出典・順位・賞金・チーム等が完全一致する既掲載戦績の自動除去) / 開始時確認待ち ID 数。
- 自動掲載率 = 今回実際に追記された戦績 ID / (開始時確認待ち ID + 今回観測された新規候補 ID)。新規候補はスキャン後キューと新規掲載試行から重複なしで抽出し、開始時掲載済み ID を除く。
- 新規候補自動掲載率 = 今回の新規候補から実際に追記された ID / 今回の新規候補 ID 数。分母ゼロは null（計測対象なし）。手動・別処理の掲載、未証明の重複や競合、理由更新だけ、台帳除去を成果に加算しない。別経路による解消と不明な除去は保守的に oldOtherRemoved / newOtherNotPublished に含める。
- 直近120回を保持、最新・直近7回/30回を分母と分子の合計で集計（同じ保留候補が複数回登場する候補×実行単位。ユニーク選手率、全大会網羅率、全手動掲載との割合ではない）。同一スキャンの安全統合再試行は runId で二重計上しない。
- 完了したスキャン、または保存済み再審査がステータスを更新した場合を測定。何も変化しないクールダウンは計測を追加しない。再審査のみの場合、古い API 使用量を流用せず null を記録。観測された provider requests / scanned pages は別指標（ページと HTTP リクエストは別）。専用手動/一括掲載ジョブ・別ワークフローの重複解消は今回の率に含めない。新着/過去を合算すると同一 ID が重複する可能性があるため個別に参照。
- 現段階では既存ステータス JSON の計測基盤のみ。サイト画面の可視化や別経路の履歴統合は別途。
