# 長期運用リファクタリング 第2段階：反映処理管理台帳

## 目的と実行方法

`node scripts/publication-inventory.cjs` をリポジトリのチェックアウトで実行すると、現在の正本と承認台帳を読み、JSONで管理台帳を標準出力に表示する。保存が必要なら任意のリポジトリ外のパスへリダイレクトする。定期実行や本番再生成には組み込まない。ネットワークアクセス、データ書き込み、掲載処理の実行は行わない。

## 調査範囲

- 本番再生成：build-season-data.yml の既存の厳密な preflight パーサーが認識する処理列。
- 過去・直近自動更新：history-sync.yml / auto-sync.yml の直接記述された Node.js 掲載・訂正・重複解消・昇格コマンド。
- 同一スクリプトの dry-run と反映をまとめ、ワークフロー別の呼び出しを記録する。パスのトリガー指定は実行回数に含めない。間接呼び出し・その他のワークフロー・手動運用は本段階の分類対象外。
- 固定バッチ10本（期待90戦績）を明示的に対応付ける。既存の証拠モジュールの検証関数を使い、後日確認された名義変更も既存の厳密な検証関数で扱う。
- 正本全体のチェックサムを検査し、各戦績ID・承認・更新マーカー・確認待ち候補を照合する。更新マーカーだけで完了と判定しない。

| 状態 | 意味 |
| --- | --- |
| applied | 対応付け済み固定バッチの全件と承認、更新記録が一致 |
| not-applied | 対応付け済み固定バッチの期待ID、承認、更新マーカーがすべて不在。異なるIDによる掲載は未確認 |
| recurring | 新規候補の処理、重複監視、名義維持など、繰り返し実行する理由がある |
| review-required | 一部反映、証拠不一致、または完了条件をまだ精査していない |

全状態で maySkip=false、レポート全体で skipEnabled=false。適用済みは掲載証拠の状態であって、再実行停止・削除の許可ではない。ファイルハッシュ・ワークフローハッシュ・正本ハッシュを記録するが、承認モジュールの全間接依存関係を保証するものではない。次段階で候補を個別精査し、別名義維持、確認待ち消費、外部ID、訂正・重複解消、生成データへの影響を確認してから、隔離コピーで旧処理と新処理の結果を比較する。

## テスト

`node --test tests/publication-inventory.test.cjs`。完全な証拠、一部不足、重複ID、改変賞金、未処理候補、未適用、未知の処理の保持を検証する。実際の正本からも台帳を生成する。PRではデータと本番ワークフローを変更しない。
