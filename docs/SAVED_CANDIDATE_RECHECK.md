# 確認待ち解消強化 第1段階

過去大会の既存スキャン処理はAPI問い合わせ前に、保存済み確認待ち候補を再審査する。正確な公式カレンダー開催枠、成熟済み完全順位表、元の候補との完全一致、現在も確認済みのEpic IDと元候補IDのハッシュ、既存の公式承認アダプターを必要とする。既掲載・既審査・明示保留・不一致候補を除外。追加APIなし、API制限時も実行。参加確認の特別許可、未確認賞金、チーム賞金の新規方式、部分走査の承認条件は広げない。既存の安全統合と更新ログにより追記のみ。新着／過去双方の同一候補が矛盾する場合は保留する。

保留理由は大会ルールとラウンドに対応する承認方式からのみ採用。デュオのRound1とRound2を区別し、未登録方式・無効設定は明記。承認アダプターの順序・実際の判定は変更しない。安全統合では最新mainの候補がベースと完全一致するときだけ理由を更新し、手動修正や別の証拠を上書きしない。

savedRecheck（checked, imported, reasonUpdates, heldEvidence, apiRequests:0）とログで確認可能。全候補が自動掲載可能になるわけではなく、S43 Squads・Console Duosの新規承認は次段階。
