# 新規選手の過去成績差分調査

新規プレイヤーの本人Epic IDが確認されたら、従来の過去大会調査を止めずに、以前「調査完了」した大会を少しずつ再照合する機能です。

## 選手の登録

既存の `players.json` の `candidates` に、本人確認済みのアカウントを追加します。成績を1件も登録していない選手でも追跡できます。

```json
{
  "name": "選手名",
  "epicAccountVerified": true,
  "trackerProfileUrl": "https://fortnitetracker.com/profile/all/PLAYER/events?id=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
}
```

`trackerProfileUrl` の代わりに32桁の `epicAccountId` も指定できます。両方指定する場合は、同じアカウントを指す必要があります。本人未確認の場合は `epicAccountVerified: true` を付けず、調査対象にはしません。

既存結果のTrackerプロフィールから本人IDが確認できる選手は、従来どおり自動追跡されます。新しく登録した選手名だけでは本人照合しません。同じIDが別選手にひも付く場合は保留します。

## 自動調査の仕組み

1. 最初の実行で既存の本人確認済みEpic IDを追跡の基準として保存します。この時点では既存677開催枠を一斉再調査しません。
2. 以後、新しく確認されたEpic IDを検出して、調査完了済みの大会に差分再調査の仕事を登録します。
3. **直近2シーズンから優先**し、古いシーズンも順次調べます。複数選手が同じ大会を調べる場合、同じ順位表から一括照合します。
4. 最大 **4ページ・2大会／実行、1大会につき最大2ページ**。通常の過去大会調査の既存の総ページ予算内で実行するので、APIリクエスト数を増やしません。
5. 各ページの元のEpicアカウントIDと順位・ポイント・キル・VR・試合数を照合し、確認済み候補のみ従来の履歴チェックポイントに追加します。追加候補の掲載には**既存の公式ルール・本人確認・重複・賞金審査**が必須です。
6. 途中の進捗は `history-sync-scan.json` の `newPlayerBackfill` に保持。API 429が出たら確認済みページを保持し、既存の再試行待ちと同じ方式で中断します。

`history-sync-status.json` の `newPlayerBackfill` と GitHub Actions の実行サマリーから進捗を確認できます。調査完了済み開催枠の状態は書き換えません。現在の調査対象シーズン・期間と大会カタログに存在しない大会、未登録の地域、元データ未取得の選手の成績は推定しません。

## 制限と注意

- これは**新規登録以降の差分調査**です。最初の導入時点ですでに追跡されていた選手は、通常の過去大会収集が引き続き担当します。
- 「大会の調査完了」は「現在登録されているすべての選手の成績が見つかった」という意味ではありません。新しい選手は別途再照合します。
- チーム戦では本人が分かっても、チームメイトのアカウント確認が不足すると既存の照合処理により保留されます。
- 上位の条件までしか取得していない旧大会は全順位表の取得に時間がかかる場合があります。API制限・公式結果欠損の際は安全に止まり、未確認賞金を作りません。
- 公開成績は本人UUIDと公式ルールによる承認済み結果のみ。重複レコードの自動上書きや推測賞金の付与は禁止です。
