# 長期運用 第4段階：戦績追加・承認処理の共通化（初回）

11月21日モバイル大会の4バッチ（39戦績、個人賞金合計$9,250）を対象とする。元の4実行ファイルは入口として残し、`scripts/mobile-screenshot-publication.cjs` の共通処理へ移行。従来コードを比較し、証拠モジュール、件数、賞金、UUIDの配列位置、既登録選手条件、更新履歴、出力ラベル以外の処理が同じであることを確認した上で抽出した。

共通エンジンは登録済みバッチのみに対応。既存の独立証拠モジュール、公式ルール、ハッシュ、名義の厳密照合、重複判定、全件一括追加、賞金の差分検証、全承認の監査、更新履歴の検証、dry-run、元のJSON書き込み順序を維持する。独自の証拠を緩めたり、未知の入力をそのまま掲載したりしない。

- 旧入口はそのまま使用可能。例：`node scripts/apply-mobile-series-nine-20261121.cjs --dry-run`
- 共通入口の例：`node scripts/mobile-screenshot-publication.cjs mobile-series-nine-20261121 --dry-run`
- 将来同一条件のバッチは登録情報と独立証拠を追加し、共通処理を再利用できる。ただし新しい証拠の監査登録・本番起動経路・テストは別途必要。
- 第3段階の再実行省略は4入口だけでなく共通エンジンのGit blobハッシュも照合する。変更があれば旧dry-run + applyへ戻す。隔離統合テストで再実行時の同一性を確認する。
- 新規・既存・改変・部分掲載・本人名義競合を元証拠を使用したメモリ内テストで確認する。実データには書き込まない。

他の大会、11月26日のTouch-Only Test Cupを含むバッチ、動的自動承認は今回対象外。戦績、賞金、承認台帳、公開画面、API、実行スケジュールは変更しない。全体共通化は段階的に行い、特殊な大会ルールを無理に統合しない。
