# 変更範囲によるCI最適化

PR上の変更を判定して、必要なテストだけを必須にします。PRをマージする前には従来のチェック名
「JSON検証・単体テスト・PCスマホ回帰テスト」が必ず成功する必要があります。

## データ専用モード（data）

対象：追加・変更のみで、次の4ファイルしか変更されないPR

- results.json
- players.json
- tournaments.json
- updates.json

削除・リネーム・ファイル種類変更は対象外です。厳格なデータバリデーション・Tracker登録ドライラン・
データ関連のユニットテストを実行します。ローカルCI内でシーズン索引を再生成し、
PC・スマホで全期間の件数、結果一覧、シーズン切替、賞金ランキングを表示確認します。

**全画面のPlaywright 4分割テストはデータ専用モードに限って省略**されます。
ただし軽量PC/スマホテストが失敗した場合は、必須ゲートも失敗します。

## フルモード（full）

上記以外のすべての変更は従来どおり、JSON検証・全ユニット・PC/スマホの全E2Eを実行します。
UI、JS、CSS、HTML、scripts、tests、workflows、package、未知のJSON、生成済みseason-data
の変更はもちろん、複数種類を混ぜたPRも必ずフルモードです。push・手動実行もフルです。

## 安全性

1. PRの変更判定には、PRで追加されたスクリプトではなく、ベースコミットに公開済みの
   scripts/ci-change-scope.cjs を使います。
2. ベースに分類器が存在しない初回PR、無効なGit参照、差分の取得失敗、予期しない変更はフル。
3. 必須の集約ジョブは「data＝unit＋PC/スマホ軽量テスト成功」または
   「full＝unit＋4分割E2E成功」のみ許容。判定失敗や不自然なスキップは不合格。
4. 変更範囲の判定だけではデータの正しさは保証しないため、賞金・重複・参照・ルール検証は維持。

最初の導入PRは保守的にフルモードです。通常の戦績追加PRからデータ専用モードが適用されます。
