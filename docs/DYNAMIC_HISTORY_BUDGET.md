# 確認待ち解消強化 第4段階

歴史スキャンの実効上限は従来通り通常48ページ・429復帰時24ページ（設定上限96を増やさない）。新規選手差分最大4ページを先に同じ予算から引く。失敗した順位表取得も1ページ試行として消費する。HTTP内部再試行・大会一覧取得・間隔・429停止条件は変更しない。

既存の開催枠選択（年・地域・シリーズ・期限到来リトライ・新規枠優先）を維持。復帰時は差分用余裕を引いたページ数以内に選択枠数を制限する。動的モードは厳密な保留理由・公式規則/有効経路・元候補完全一致・ページ連続性・未掲載/未審査の候補が選択されたときだけ有効。順位表を増やしても解決しない地域別通過条件不足、本人ID不一致、公式日程不足、無効承認経路は回収優先対象にしない（通常調査は継続）。旧汎用保留理由に加え、NVIDIA/PS/Cash/Duo/Squadsの明示された順位表不足理由を対象にする。

選択済み枠に基本1ページ、期限到来リトライと未調査枠を保護し、設定された未調査枠数まで2ページを確保。余裕のある範囲で候補回収に最大60%を配分し、完了可能な順位表と候補数/未確定賞金の優先順位を使う。残りは他の近完了・未調査等へ配分。各枠最大12ページは維持。選択順・終了期限・バックオフを変更しない。通常配分へのフォールバックあり。選択枠数や新規枠の実数、解消件数はデータ次第で保証しない。安全上の未使用予算は無理に消費しない。status.dynamicReviewBudgetに分類別予定/試行/取得ページ、候補数を記録し、API実測は既存providerTrafficと比較する。賞金・承認条件・戦績データは変更しない。
