# ASIA ON TOUR

## データ検証センター v1.1：管理者による安全な掲載申請（2026-11-06）

公開閲覧者に編集・承認権限を渡さず、GitHub Actions上で管理者が候補の承認を申請できるフローを追加しました。公開ページの「確認待ち」タブで対象IDを選択し、コピーしてから、Actionsの **AOT reviewed candidate publication request** を実行します。

1. GitHub Actionsの「Run workflow」で `candidate_ids` に1～20件の候補IDを入力。 `publication_policy` は「attendance-only」（参加確認のみ）または「verified-rule」（既存公式規則で検証可能な予選突破・決勝0VR）。 `confirmation` を明示的にCONFIRMにします。
2. 既定の `preview_only: true` では候補とスキャン済み順位表・大会マスター・本人確認・公式開催枠・既存の重複を照合し、**結果JSONは更新せず**承認プレビューをActionsのartifactに14日保存します。
3. 照合内容を確認したら `preview_only: false` で再実行。最新のmainから候補を再照合し、JSON検証と承認テストを通過した場合だけ、`reviewed-results/<run-id>` ブランチへコミットし、Pull Requestを提案します。**mainへ直接Pushしません**。
4. PRで戦績差分・対象ID・個人賞金・出典・GitHub Actionsのテストを確認し、管理者がマージした後に正式掲載となります。マージ前にmainが更新されていれば、競合や重複を再確認します。GitHub ActionsからのPR作成が組織設定で禁止されている場合はブランチ作成までで失敗し、管理者がそのブランチから手動PRを開く必要があります。
5. 掲載された候補は両方の確認待ちJSONから該当IDだけ除き、`approval-history.json` に出典・承認ポリシー・日時を記録、`updates.json` に履歴を追加します。残りの候補・正式記録・賞金・選手名・大会マスターは維持します。

安全条件：元の候補と順位表スキャンの重要項目が完全一致、公式EpicイベントID・ラウンド・地域・JST開催日と大会カタログが一致、参加者全員が確認済み名鑑と一致、数字が有効、既存に同一IDや同一選手・開催枠がないことを必須とします。ラウンドの識別が不足する同日・同大会・同一選手の記録は**推測で追加しません**。公式順位表の収集途中でも、順位表に記録済みの個別候補を確認できる場合に限り、「参加確認」だけを扱えます。

**未確認の賞金・スキン報酬・予選突破は承認操作だけでは確定できません**。現金賞金が正の記録は今回の申請機能では自動処理を禁止し、公式ルール・受賞資格・個人配分まで人間が確認する既存の管理者更新フローに残します。承認種別を変更してもこの制限を迂回できません。

実装：`scripts/manual-approval-core.cjs`、`scripts/manual-approval.cjs`、`.github/workflows/reviewed-candidate-publication.yml`、`approval-history.json`、データ検証センターのID選択UI。検証：`node --test tests/manual-approval.test.cjs`。この機能は公開GitHub PagesからAPI書き込みを行いません。

## データ検証センター（2026-11-06）

公開ページの「データ検証センター」（verification.html）から、直近のAUTO SYNCと過去大会の確認候補、掲載済み戦績の重複・大会枠分裂疑い、不正な基本数値、未登録大会ID、月別・地域別の掲載状況、サイト更新と過去候補の処理履歴を参照できます。

- サイドバーから移動可能。更新履歴のAUTO SYNC管理パネルと大会カレンダーにもリンクを追加しました。PC・スマホ対応、カテゴリ切り替え、検索、地域フィルター、50件ずつのページ移動、画面からの再読み込みに対応。
- verification-core.js は読み取り専用の検査エンジン。results.json、auto-sync-review.json、history-sync-review.json、auto-sync-status.json、history-sync-status.json を都度読み込みます。補助データとして history-sync-reviewed.json、updates.json、calendar-history-status.json を利用。正式な結果や候補データを変更しません。
- 同一IDの重複・内容矛盾、同一選手・日付・地域・大会・段階・識別できたセッションの複数レコード、同日の「決勝」「賞金決勝」の混在を「要照合候補」として提示します。出典の公式ウィンドウが確認できない場合は自動統合しません。予選と決勝・異なるEvent/Session・同名別人の誤統合をしません。
- 未確認の数値は null として扱い、0へ補完しません。スキン大会の現金賞金・負数・必須項目欠落などの基本的な不整合を表示します。ただしこの画面の検査は全チェックを再実装したものではありません。公開前の厳密な構造・出典整合性検証は従来の scripts/validate-data.cjs とGitHub ActionsのCIを利用してください。
- 月別・地域別の掲載数は調査完了率ではありません。現在候補が0件でも未調査大会がないとは断言しません。未登録大会IDは収集側のスナップショットから参照し、未確認の大会を自動作成しません。
- history-sync-reviewed.json の判断履歴と updates.json の公開履歴を参照でき、公開サイト側では候補の採否・賞金の訂正・削除・GitHub書き込みはできません。承認・修正は管理者が従来のGitHubワークフローで行い、CI合格後に公開します。
- 必須JSONの取得に失敗した場合は0件と誤表示せずエラーにし、検証数値を非表示にします。出典リンクは許可したHTTPSサイトに限定し、候補由来の文字列はHTMLとして解釈せず文字列表示します。

実装：verification.html、verification.css、verification.js、verification-core.js。単体テストは node --test tests/verification.test.cjs、PC・スマホ画面は npx playwright test tests/verification.spec.cjs で検証します。

ASIA勢のFortnite海外大会戦績を検索・閲覧する、GitHub Pagesの閲覧専用サイトです。一般閲覧者による戦績の追加・削除・保存・アップロード機能はありません。

## 選手比較機能（2026-11-04）

メニューの**「選手比較」**から2〜3人の選手の海外遠征成績を同一条件で比較できます。選手名入力は既存の登録選手・確認済み別名義のみを採用し、別人の同名選手を勝手に統合しません。選手プロフィールの「⚔️ 他の選手と比較」から始めることもできます。

- **指標**：現行の独自算出式を再適用したAOT PR、確認済み個人現金賞金、掲載VR合計、正の順位が確認できる決勝出場、賞金決勝TOP3、個人賞金獲得戦績数、遠征地域数、出典確認済み掲載戦績数。6地域別の確認済み個人賞金と掲載件数も横並びで表示
- **公平な比較条件**：全期間／シーズン別（サイト上部のシーズン選択と同期）、海外地域、ゲーム形式、シリーズを2〜3人すべてに共通適用。各指標の最多値を表示し、数値バーで比較
- **データの信頼性**：`verified===true` の掲載成績のみ。重複した同一IDを除去し、矛盾する重複IDは集計せず、賞金は確認済み個人分のみをカウント。チームのVRはチーム戦績のVRとして表示し、未確認VRはゼロと決めつけない。大会未登録や未確認のデータを推測で埋めない
- **共有**：`#compare?player=<名前>&player=<名前>&region=ME&mode=reload` などで選手の組み合わせと比較条件を直接共有。ブラウザーの履歴や再読み込みから比較を復元可能
- **実装**：`compare.js`（比較集計エンジン）、`compare.css`（PC/スマホの比較画面）、`app.js`（検索・選択・URL同期）。既存の戦績JSON、プロフィール、PRや称号計算コードは編集せず再利用
- **検証**：`node --test tests/compare.test.cjs`（個人賞金、確認済みVR、重複除外、共通フィルター等）、`npx playwright test tests/compare.spec.cjs`（PC/スマホの選手追加・削除・比較画面・共有・戻る操作）

## 大会別・開催日で探す機能（2026-11-04）

「大会を探す」から開く大会詳細ページ（例：Solo Victory Cup Battle Royale）に、**開催日から探す**を追加。登録済みの開催日を件数・地域とともに選べます。

- 全開催日／開催日別の表示切り替え。**日付選択は開催地域や予選・決勝を勝手に限定せず、その日の全掲載戦績を表示**します。開催日の前後移動・最新の開催日へのジャンプに対応
- 各日付の表示対象に合わせて「掲載戦績・開催枠・掲載選手」の概要、「予選・決勝・賞金獲得」の段階別フィルターと結果一覧を再計算します。存在しない日付は空の結果として表示し、別日へ自動的にすり替えません
- `#tournament=<大会ID>?date=YYYY-MM-DD` で日付別の結果を共有できます。従来の `#tournament=<大会ID>` は全開催日のままです
- 大会カレンダーから移動したときの `?date=...&region=...&round=...&kind=...` の**開催枠限定表示**は維持。日付選択を操作するとその日付の全地域・全ラウンドの表示へ切り替わり、「全開催日」へ戻せます
- PC・スマホのカレンダーおよび大会詳細の回帰テスト（`tests/calendar.spec.cjs`）で選択・共有・履歴移動・既存リンク・スマホレイアウトを検証。大会結果JSONと賞金や称号のデータは変更していません

## 選手プロフィールの成長グラフ（2026-11-04）

選手プロフィールに**全期間の海外遠征成長グラフ**を追加しました。`growth.js` が確認済みの掲載戦績から時系列を作り、`growth.css` と `app.js` で折れ線グラフ・期間選択ボタン・数値表を描画します。

- **月別／シーズン別**を切り替え可能。シーズンは日付から推定せず、既存の大会カタログと明示的なSeason IDの確認結果を使い、未確認は季節別表示から除外します
- **累計／期間別**を切り替え可能。何月・どのシーズンで成果が増えたかを確認できます
- **4つの指標**：現行の `AotPR.calculate` 計算式を遡及適用したAOT PRの参考推移、確認済み個人現金賞金、順位を確認できた決勝出場件数、確認済み賞金決勝の総合TOP3件数
- 決勝出場には `賞金決勝`・`Practice決勝`・`Performance決勝`・`決勝` を含め、正の整数順位がある戦績のみ。TOP3は既存ランキングの厳格な賞金決勝順位判定を再利用します
- **未掲載の月**は線を平らに描くため掲載0件の月として表示しますが、本人が大会に参加しなかったとは断定しません。掲載済みの確認済みレコードのみ集計し、未確認別名義や不明な個人賞金は補完しません
- グラフは全期間の実績から算出され、画面上の集計対象シーズンを切り替えても累計を失いません。AOT PRは過去の公式順位や実際の時点の強さを再現するものではありません
- スマホでは横スクロールできるSVG折れ線グラフ、タップ可能な期間選択ボタン、詳細を確認できる数値表を提供。既存の成績・選手・大会のJSONは変更しません

動作検証: `node --test tests/growth.test.cjs` と `npx playwright test tests/growth.spec.cjs`（PC・スマホ）

## 特別称号の累計進化 v4（2026-11-03）

地域別スペシャリストは、各地域の**掲載済み・確認済み海外戦績数**に応じた5段階の進化称号に変更しました。6地域のバッジは独立して成長し、同じ地域の称号カードが重複して増えることはありません。

| 累計戦績数 | 呼び名（MEを例に） | メタルランク | 特別称号レア度 |
|---|---|---|---|
| 5件 | MEスペシャリスト | ブロンズ | レア |
| 10件 | MEエキスパート | シルバー | レア |
| 20件 | MEマスター | ゴールド | エピック |
| 40件 | MEレジェンド | プラチナ | エピック |
| 80件 | MEの覇者 | プリズマティック | レジェンダリー |

「二刀流」は、**個人現金賞金を獲得した大会の編成種類**で進化します。ソロ・デュオ・トリオ・スクワッドのうち、異なる2形式で「二刀流」、3形式で「三刀流」、4形式で「四刀流」。同じ形式で何度獲得しても1形式として数えます。二刀流／三刀流はエピック、四刀流はレジェンダリーです。ソロがなくてもデュオ＋トリオなど2形式を満たせば二刀流を獲得できます。

判定は従来の個人受取額確認ルールを使い、大会マスター上の編成と完全なチーム構成から形式を識別。ソロは大会名の「Solo」などでも確認できる場合のみ採用し、人数不明、名義の類推、チーム賞金の個人取り分不明、カタログとの矛盾は除外します。新しい掲載記録に応じて**全期間累積で自動更新**し、達成カードには現在の段階、次ランクまでの残り、進捗バー、全段階の目標および確認できた大会の記録を表示します。既存のバッジID、6系統の進化バッジ、全成績データを保持します。

## AOT POWER RANKING v1.11

名鑑の上部に、選択シーズンの掲載済み海外戦績から自動計算した独自ポイントを上位50名まで表示します。ALLと6開催地域を切り替えられ、選手名からプロフィールの参加・順位・キル・予選突破・賞金獲得ボーナス別内訳と大会ラウンドごとの得点を確認できます。既存の賞金ランキングとは独立しており、現金賞金へ換算しません。公式PRや選手の絶対的な実力順位ではありません。

1ラウンドの得点は `(参加点 + 順位点 + キル点) × 地域倍率 + 予選突破ボーナス + 賞金ボーナス` です。予選突破ボーナスは対象となる確認済みラウンドにのみ付与されます。

- 参加点：開催枠の初回のみ `10 × 大会倍率`
- 順位点：`100 / √最終順位 × 大会倍率 × ラウンド倍率`
- キル点：`min(25, チーム合計キル / チーム人数 × キル係数) × 大会倍率 × ラウンド倍率`

| 倍率・係数 | 定義 |
| --- | --- |
| 大会 | FNCS Major・Heats・LCQ等1.6、Division 1・Division 1 Practiceともに1.4、Performance Evaluation 1.2、Victory/Cash Cup 1.0、スキン大会・旧Override・Inoxtag/Madison Icon 0.50、NickEh30の予選0.50／決勝1.20、その他Icon Cup 0.35、Test Cup 0.25 |
| ラウンド | 予選0.35、決勝・単一セッション1.0 |
| キル | 通常BR・通常ゼロビルド1.5、Reload・Reloadゼロビルド0.7 |
| 地域 | EU 1.40、BR 1.30、NAC 1.20、ME 1.10、OCE 1.10、NAW 1.00 |

確認済みの掲載名だけを使用し、順位・キルが未確認なら当該項目の加点を保留します。形式未確認ではキル点を保留、大会分類未確認では全体を保留します。未確認値を確認済み0として書き換えません。確認済み参加の参加点は残します。Test Cupも確認済みの掲載成績に限り、単一セッション倍率1.0と大会倍率0.25で加点します（賞金は加算しません）。Test Cupは大会シリーズ `test-cup` と戦績区分 `Test Cup` の両方が一致する場合だけ加点します。

### 確認済み予選突破ボーナス（v1.11）

- **`verified: true` かつ `kind: "予選"`** の出典確認済み戦績で、①ラウンド欄に「予選突破／予選通過」が明記、②その大会の公式ルールで確認した地域別通過順位以内かつ出典が正しいRound 1、③本人の決勝進出が検証済みの記録文に明記され、出典のイベント・地域が一致、のいずれかに該当する場合、**同じ選手・大会・日付・開催枠につき 10pt × 開催地域倍率** を付与します。例：NAWなら10pt、EUなら14pt。

| 掲載済み決勝出場記録 | 確認済みで順位・ポイント等の実戦績がある決勝記録。報告のみ・部分情報・予選通過だけの記録は除外。賞金／Practice／Performance／その他の決勝を分離 |
| 決勝総合優勝／TOP3 | 年表と共通の賞金決勝判定を使用。確認済み総合順位が整数1位／1〜3位。通常の「決勝」や試合単位のVRから推測しない |
| 海外VR合計 | 確認済み・非負整数のVRを合計。予選・決勝・コスメを含む掲載分。デュオ等はチームVRを各選手に付与し、単独勝利回数とは区別 |
| 遠征地域数 | 条件に合う掲載戦績の開催地域（ME/EU/NAC/NAW/OCE/BR）の種類数。全地域選択時のみ |
| スキン獲得回数 | 年表と共通の確認済み獲得判定を使用。スキン大会のラウンド欄に独立した「スキン獲得」「スキン報酬獲得」（または「済み」付き）が明示された記録のみ |

VRが未確認の戦績は0として補完しません。確認済み0VRは順位付き、確認できるVRがない選手は「未確認・順位なし」の別一覧に表示します。確認済みと未確認が混在する場合は、確認できた合計と除外件数を併記します。どの項目でも集計対象は掲載記録だけであり、公式ランキングや実際の全成績を意味しません。

同一IDの完全一致は1件として数え、内容が衝突する同一IDは対応確認まで全件除外します。別IDでも、確認済み大会識別子・明示された出典ラウンドID・開催日・地域・選手・戦績数値がすべて一致する記録だけを重複として除外します。異なる予選／決勝／セッション、ラウンドID未確認の記録は推測でまとめません。除外件数は画面に表示します。

選手は既存の正規化済み掲載名（`players`／`player`）を使用し、別名義は既存の確認済み対応を維持します。表示名の類似やTracker IDから新たな統合を行わず、`p1ng`と`RGN p1ng`も別選手です。データJSONは変更しません。

ランキングのテスト：

```sh
node --test tests/rankings.test.cjs
npx playwright test tests/rankings.spec.cjs
```

集計テストでは既存全シーズンの個人賞金・ランキングとの一致、個人配分、同順位、重複とセッションの分離、未確認値、地域・形式・大会シリーズを検証します。画面テストはPCとスマホで条件復元、プロフィール遷移、キーボード操作、空状態、段階表示、横はみ出しを確認します。既存JSONの検証は別途実行し、既存データの不整合をランキングテストで免除しません。

## 海外遠征年表（OVERSEAS JOURNEY）

各選手のプロフィールに、選択中のシーズンの主な実績だけを古い日付から並べたハイライト年表を表示します。初期表示は「主な実績」で、「賞金獲得」へ切り替えることもできます。年表の「全戦績」表示は重複を避けるため廃止し、全記録は下の「海外大会履歴」に残します。年表のハイライト・賞金獲得は30件ずつ追加表示できます。

- ハイライトは、掲載記録上の初賞金獲得、確認済み賞金決勝の総合優勝・TOP3、累計個人賞金の節目、掲載記録上の初スキン報酬獲得に限定します。VR・初掲載・新地域・自己最高更新・予選通過・通常のPractice入賞だけでは掲載しません。複数の理由は同じ戦績カードにまとめ、0件の場合も正常に表示します。
 - 累計賞金グラフは、年表に表示するハイライトだけではなく、選択シーズンの全登録戦績を集計します。下の海外大会履歴も完全なまま維持し、未確認データを消しません。
- 初獲得と累計節目は、選択期間だけでなく登録済み全期間で判定します。節目は$1,000・$5,000・$10,000・$50,000・$100,000…（1と5の区切り）です。未掲載の過去大会があり得るため、実際の初獲得・生涯記録とは断定しません。
- 同日内の時刻は推測しません。初賞金・初スキン報酬は該当日の獲得記録、累計節目は到達日の現金獲得記録にラベルを付けます。賞金の節目は日末値で判定します。日付不明の現金獲得がある場合は初賞金日と累計到達日、日付不明のスキン獲得がある場合は初スキン報酬日を断定しません。
- 総合入賞は、確認済み・区分が「賞金決勝」・総合順位が整数1〜3位の記録だけです。Practiceやスキン大会を総合入賞へ転用しません。初スキン報酬は、確認済みのスキン大会でラウンド欄に「スキン獲得」「スキン報酬獲得」（または「済み」付き）が独立して明記された記録だけを使い、順位や参加だけから推測しません。
- 累計個人賞金グラフは選択期間の各日終了時点の値です。表示モードによって集計対象は変わりません。既存の個人配分ロジックを使用し、予選VR・コスメ・未確認賞金を現金へ換算しません。日付が不明な賞金はグラフ対象外であることを明示します。
- 選手の所属判定は既存の掲載名の完全一致を維持し、似た名前やTracker IDから統合しません。同じ大会の予選・決勝も戦績ID単位で別々に保持します。

年表だけを確認する場合：

```sh
node --test tests/journey.test.cjs
npx playwright test tests/journey.spec.cjs
```

ロジックテストは実データ全選手の戦績ID・個人累計の保持と合成データによる日付・区分・不明値を検証します。ブラウザーテストはPC／スマホで3表示モード、過去シーズン・全期間、個人配分、別人の分離、出典・大会リンク、30件ずつの表示、長い大会名の横幅を確認します。合成データはテスト中だけ使用し、公開JSONへ保存しません。

## テストの実行

Node.js 22以上（CIは24）とnpmを用意してください。開発依存はPlaywright Testのみで、バージョンと依存関係を`package-lock.json`に固定しています。JSON検証と単体テストはNode.js標準機能のみで動作します。

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
```

Linuxでシステム依存が不足する場合は、`npx playwright install --with-deps chromium`を使用します。

```sh
npm run validate       # JSON構文・形式・参照と個人賞金の検証
npm run test:unit      # 不正データの拒否と画面ロジックの回帰テスト
npm run test:e2e       # ChromiumでPC・スマホの実ブラウザーテスト
npm run serve         # http://127.0.0.1:4173 で閲覧用プレビュー
```

インストールなしの確認は`node scripts/validate-data.cjs`と`node --test tests/*.test.cjs`で実行できます。別フォルダーのJSONを公開前に調べる場合は、`node scripts/validate-data.cjs <JSONを置いたフォルダー>`を使用します。

## 検証ルール

- JSON構文、配列／オブジェクト、必須フィールド、戦績ID・大会ID・名鑑名の重複
- 日付、地域、順位・ポイント・キル・VR・賞金の形式、出典・プロフィールURL
- タグの存在、ソロ／デュオ人数、出典の大会・ラウンドIDと地域・シーズンの整合性
- 別名義の対応先、複数人への同じ別名義の割り当て、別人への統合、TrackerアカウントIDの衝突
- 過大な個人配分、予選VR・コスメ報酬・未確認賞金の現金への混入
- 画面の件数・ランキング・プロフィール・地域グラフとJSONの独立集計との一致
- 検索・複合フィルター・CSV・共有URL・期間・大会タグ・読み込みエラー表示・横はみ出し・閲覧専用設計

戦績の必須フィールドは`id`・`date`・`region`・`player`・`event`・`round`・`rank`・`points`・`kills`・`vrs`・`prize`・`kind`・`source`・`verified`・`note`です。不明な数値は推測せず`null`、確認済みゼロは`0`にします。順位は1以上、他の戦績数値は0以上の整数、賞金は小数2桁以内の非負数です。フラグは文字列ではなく真偽値を使用します。

チーム戦績の`players`には重複のない掲載名を並べ、`prize`にチーム合計、`prizePerPlayer`に確認済み個人分を保存します。個人配分不明の賞金を均等割りで補完せず、予選VRやスキンを現金へ換算しません。正の賞金でも`verified: false`なら個人合計に含めません。

別名義は`confirmedAliases`の明示的な対応だけを使用します。似た表示名・チーム名・Unicodeの見た目から自動統合しません。`p1ng`と`RGN p1ng`は別選手です。ソロのリンク名には既存の`playerRaw`表記も認めます。チームのプロフィールは各掲載名または確認済み別名義との対応が必要です。

未確認の大会形式・シーズンを推測で補完しません。カタログ未登録などは「要確認」の警告、存在しない明示的な参照や矛盾した識別子はエラーです。シーズンの追加は[SEASONS.md](SEASONS.md)、大会分類は[TOURNAMENTS.md](TOURNAMENTS.md)も参照してください。

## 固定値と人間の確認

テストに「138件」「$9,000」を恒久的な正解として埋め込んでいません。件数・賞金・ランキング・期間別集計をJSONから毎回計算し、正当な追加分も含めて画面と一致することを検証します。単体テストの架空データの件数・額はテストケース専用です。

導入時には既存138戦績を保持し、個人賞金$9,000が変更前と一致することを確認しています。この数字は導入時点の記録であり、将来の上限・固定値ではありません。

エラー例：`エラー results.json [戦績／対象ID: example-id] prizePerPlayer: 個人配分の人数分がチーム賞金を超えています…`

エラーはファイル・戦績ID（または選手／大会ID）・項目・日本語の理由を表示し、終了コード1で失敗します。JSON自体が壊れてIDを読めない場合は「ファイル全体」です。GitHub Actionsではエラー注釈も付きます。「要確認」は人間が調べる項目で、構造エラーと区別します。

**自動検証は実際の大会結果の正しさを保証しません。** 出典の順位表・画像、開催日、順位、本人確認、賞金の根拠は人間が確認してください。`verified: true`という入力を、機械による事実認定とは扱いません。外部サイトへの自動照会や書き込みは行いません。

## GitHub Actions

`.github/workflows/tests.yml`がPush・Pull Request・手動実行時に、JSON検証 → 単体テスト → PC／スマホのブラウザーテストを実行します。依存パッケージはロックファイル、公式ActionsはコミットSHAに固定しています。

結果はActionsの「Data and site tests」で確認できます。`site-test-report`にHTMLレポートと、失敗時のスクリーンショット・トレースを7日間保存します。PRで成功を確認してからマージしてください。このワークフローだけで、直接Push時に別のGitHub Pages配信が自動停止するわけではありません。

```sh
npx playwright show-report
```

`node_modules`・レポート・トレースはGitへ登録しません。アプリやJSONを変更したときもテストを実行してください。


## ホームの注目選手・注目記録

ホームに「注目のプレイヤー」と「注目の記録」を表示します。既存の `results.json` ・大会カタログから、その時選択中のシーズンに合わせて毎回自動計算します。過去の固定スポットライトや名鑑先頭3名の固定選抜は廃止しました。

- **注目のプレイヤー**は「確認済み個人現金賞金トップ」「AOT PR総合トップ」「確認済み海外VRトップ」の各部門で表示します。同じ選手が複数部門に登場する場合はそのまま表示し、2位を1位と偽らないようにします。
- 賞金は既存の `prizeTotals` / `individualPrize`、AOT PRは `AotPR.calculate`、VRは `AsiaRankings.buildRankings` の検証済み集計を再利用します。未確認賞金・スキン・予選VRを現金に加算しません。AOT PRは公式ランキングではありません。
- **注目の記録**は「登録済み単一戦績の最高確認済み個人賞金」「直近の確認済み賞金決勝総合TOP3」「直近の明示確認済みスキン報酬獲得」から、それぞれ1件選びます。3部門で同じ戦績IDが並ばないようにします。対象がなければ記録を捏造せず、表示しません。
- 注目選手からは本人のプロフィールへ、記録カードからは大会・選手プロフィール・Fortnite Trackerの出典へ移動できます。
- 対象はサイトに掲載された実績に限ります。大会未収録分まで含めた選手の真の実績ランキングではありません。

## 選手プロフィールの海外遠征スタッツ

`#player=` で開く選手プロフィールには、従来の賞金・最高順位・AOT PR・遠征年表・地域別チャートに加え、次の実績パネルがあります。

- **確認済みKILLS / VR**：選択中のシーズンで `verified: true` かつ0以上の整数として記録された値だけを合算します。`null` や未検証記録を0と扱わず、対象件数を併記します。デュオ等ではチームのキル・VRを含み、選手個人が単独で記録した数値ではありません。
- **順位確認済み決勝**：`賞金決勝`・`Practice決勝`・`Performance決勝`・`決勝` で、出典確認済みかつ有効な総合順位がある掲載件数です。予選通過や試合単位のVRから決勝成績を推測しません。
- **スキン報酬獲得**：既存の厳格な `confirmedSkinReward` 判定を再利用。出典確認済みの明示的獲得だけを数え、コスメ報酬を現金に換算しません。
- **ゲーム形式別**：登録大会カタログの形式で通常BR・ゼロビルド・リロード・リロードZB・形式未確認を分けます。形式未確認を推測で既知形式に分類しません。
- **掲載された相方**：同じ戦績の `players` 配列にいる別の選手だけを数えます。確認済みの掲載名を完全一致で比較し、旧名義や同名別人を推測で合体させず、固定デュオであるとは断定しません。相方の名前からそのプロフィールを開けます。

表示は現在の集計期間に従います。これらの情報は `results.json` と既存の大会分類から閲覧時に導出し、元データに推測値を保存しません。



## 大会詳細：予選 → 決勝 → 賞金獲得

大会詳細ページに、ラウンドの流れを把握する集計・注目戦績・表示切り替えを追加しました。

- **全戦績／予選／決勝／賞金獲得**の4モード。既定では全戦績を表示し、ボタンから下の開催枠一覧だけを切り替えます。既存の地域・日付・ラウンド分離は維持し、JSONの戦績を削除したり書き換えたりしません。
- **予選掲載**と**突破確認済み**を別カウントします。「突破確認済み」は `verified: true` かつ区分が `予選` で、ラウンドに「予選突破」「予選通過」が明記されている場合だけです。順位や勝ち数だけから進出を推測しません。
- **決勝掲載**は `賞金決勝`・`Practice決勝`・`Performance決勝`・`決勝` です。決勝に出た事実と賞金獲得は区別し、賞金表示は既存の `isPrizeWin` と `archivePrize` に従います。予選・スキン報酬は現金賞金へ混ぜません。
- **各段階の注目戦績**は、突破が明記された予選・順位を確認できた決勝・確定現金賞金の掲載記録から最大4件ずつ抜粋。選手名のリンク、順位・日付・地域、個人賞金が確認できないデュオの内訳表示方針を維持します。
- **予選と決勝の両方が掲載される選手**は、掲載名が完全一致し、同じ開催地域・日付・明示された `Event`・`Week`・`Session` 番号を共有する場合にのみ照合します。未確認の識別子や類似名を推測で結びません。これは登録上の同時掲載を表し、通過ラインの独立した検証ではありません。
- 集計値は選択シーズンに連動します。下部の開催枠別の全レコードへいつでも戻せます。


### 出場戦績アーカイブの基本AOT PR（v1.9）

- Osirionの大会順位表と本人Epic IDが確認済みで、月別`participation/YYYY-MM.json`の出典・大会ID・地域・順位・キル・試合数が整合する記録だけを使います。**正式戦績の`results.json`や賞金額は変更しません**。
- 同じ選手・大会・開催日・地域・Event/Session/Week/Dayにすでに正式な戦績があれば、その選手のアーカイブ側の参加・順位・キルの加点を抑止します。開催枠が不明な場合は安全側で重複扱い。デュオ等で片方のみ正式掲載済みなら、もう一人だけ加点します。
- 基本点は`参加点（初回10pt）＋順位点＋キル点`に既存の大会・地域倍率を適用。予選または詳細段階未確認のアーカイブは、順位・キルの係数を保守的に**0.35倍**として扱います。
- **賞金ボーナス・予選突破ボーナス・スキン獲得・称号は増やしません**。AOT PRランキング、選手プロフィールの個別PR内訳、成長グラフのPR、選手比較のPRに基本ポイントだけ反映します。賞金・VRの正式集計・決勝実績・称号は従来の掲載済み戦績のみです。
- ブラウザーでは月別ファイルを最大4か月ずつ読み込み、反映後にPRを再計算します。取得不能な場合は従来の正式戦績だけのPRを維持します。全大会の網羅は保証しません。
- 実装：`participation-pr.js`（信頼できる記録の検証と重複除外）、`aot-pr.js`（加点）、`participation-ui.js`（月別ファイル読込）、`app.js`（PR表示・比較・成長グラフ）。`node --test tests/participation-pr.test.cjs`で二重加点、未知の本人・大会・出典、不正な数値、賞金加点防止をテストします。
